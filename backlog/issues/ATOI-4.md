## Context

US-18: a notification on the phone when a Décision waits and the Pilote is away, « away » meaning no Crewdeck tab visible for 2 minutes, so the agents do not stay stuck for hours. ADR 0007 settles the mechanism: each tab sends its visibility on every `visibilitychange`; when a Décision is created the server pushes at once if no tab has been visible for 2 min, else it checks again 2 min after the last visible tab hides; Web Push (VAPID, `web-push`) to the installable PWA (on iOS 16.4+, added to the home screen); the payload is the Décision's title and its link, Idées give a generic title; the Paramètres' « Notifications push » registers the Appareil's subscription. Every Décision kind gets it, « Runner hors ligne » (ATOI-3) included.

- **Subscriptions** `apps/server/src/notifications/`:
  - Prisma model `PushSubscription` (`push_subscriptions`): `id`, `pilotId`, `endpoint` (unique), `p256dh`, `auth`, `label` (≤ 60, e.g. « Safari · iPhone »), `createdAt`, `lastPushedAt?`;
  - `POST /api/push-subscriptions { endpoint, keys: { p256dh, auth }, label }` (an existing endpoint is updated, returns the resource), `GET /api/push-subscriptions` (the Pilote's, at most 20), `DELETE /api/push-subscriptions/:id` (204, 404 for another Pilote's); contract `packages/contracts/src/api/push-subscriptions.ts`;
  - `GET /api/config` gains `vapidPublicKey`.
- **Rule** `apps/server/src/notifications/push-rule.ts` (fake clock in tests), on a Décision `created` (after commit):
  - the account's `notifications.push` is off, or the Décision's Projet has it off (`SettingsService.effective(pilotId, projectId)`) → nothing;
  - no tab visible and `lastVisibleAt` older than 2 min (or none) → push now;
  - else a timer 2 min after the last visible tab hides; when it fires and still no tab is visible, push the open Décisions created since the Pilote's last push (`decisions.notified_at` null, column added here);
  - one Décision → title « <kind label> · <label> », `url` its `link`; several → « <n> Décisions t'attendent », `url` `/a-toi`; kind `ideas-to-triage` → « Idées à trier »; no other text;
  - `web-push` with `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`; a 404 or 410 from the push service deletes the subscription; `notified_at` set on what was sent.
- **Paramètres** (« Notifications » card in the `notifications` Emplacement of `/parametres`): the `Toggle` « Notifications push » (the account's `notifications.push`, `PATCH /api/settings`) with the mockup's help; the list of subscriptions (`ListRow` label, « autorisé le <date> », « Retirer » → `DELETE`); « Activer sur cet appareil » when this browser is not subscribed (permission asked, `pushManager.subscribe({ userVisibleOnly: true, applicationServerKey })`, then `POST`); where `PushManager` is missing, or on iOS outside the home-screen app, the help « Sur iPhone, ajoute Crewdeck à l'écran d'accueil (Partager → Sur l'écran d'accueil) pour recevoir les notifications. » instead of the button.

## Decisions already made

- Mockup: `parametres` (page `design/screens/crewdeck/parametres.html`; captures `…-390.png`, `…-1280.png`), its « Notifications » card only. It gives the look, this ticket the scope: an element of the mockup absent from this ticket is not built, its filler text is not copied, and the screen is composed with the design system's components (`design/DESIGN.md`); the page's HTML and CSS are a reference, not code to copy.
- A subscription belongs to a browser, not to an **Appareil** of ADR 0003: « Retirer » removes the push, never the Appareil's trust (that is E2E-4).
- The label is built in the browser from the user agent (browser · system), never sent elsewhere.
- One server process at the MVP: presence and timers are in memory; a restart loses the timers, and the next Décision or the next hide restarts them (acceptable at the MVP, ADR 0001).
- Payloads carry only the Décision's kind, its readable label and a link (ADR 0003).

## Acceptance criteria

- [ ] A Décision raised while no tab is open is pushed at once to every subscription of the Pilote.
- [ ] A Décision raised while a tab is visible is not pushed; it is pushed 2 min after the last tab hides if still open; not at all if a tab became visible again.
- [ ] Several Décisions waiting at the timer give one notification « <n> Décisions t'attendent ».
- [ ] Push off for the account, or for the Décision's Projet, sends nothing.
- [ ] A 410 from the push service deletes the subscription.
- [ ] Clicking the notification opens the Décision's page in the PWA.
- [ ] The push-subscriptions routes follow the route baseline (400 with `fields`, 401, 404 for another Pilote's).
- [ ] The Paramètres card at 390 and 1280 matches the mockup, with the iPhone help when push is unavailable; axe without violations.
