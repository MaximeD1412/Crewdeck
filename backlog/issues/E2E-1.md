## Context

ADR 0003: conversations, code, diffs and the text of the Idées travel encrypted end to end between the Runner and the Appareils (US-60). Both sides must agree byte for byte: the browser with WebCrypto, the Runner with Go's standard library, no third-party crypto library, proven by shared test vectors. The protocol is written once, in `docs/security/e2e.md`, for the outside review before the Bêta (SEC-3). E2E-2 (pairing and vault key), E2E-3 (new Appareil), SESSION-1 (Sessions) and IDEE-1 (Idées) use these primitives.

## Current state of the code

- Created by INFRA-1: `apps/web/` (TypeScript, Vitest with browser mode), `apps/runner/` (Go module), `packages/contracts/fixtures/`.
- No crypto code, no `docs/security/`.

## To do

Each later ticket (E2E-2, E2E-3, E2E-4, SESSION-1, IDEE-1) updates its section.
- TypeScript `apps/web/src/keys/crypto.ts`:
  - `generateKeyPair(): Promise<CryptoKeyPair>` (X25519, private key non-extractable), `exportPublicKey(key): Promise<Uint8Array>` (32 bytes raw).
  - `hpkeSeal(recipientPublicKey: Uint8Array, plaintext, info, aad): Promise<{ enc: Uint8Array, ciphertext: Uint8Array }>` and `hpkeOpen(recipientPrivateKey, enc, ciphertext, info, aad)`, base mode, one ephemeral key per seal, built from WebCrypto's X25519 `deriveBits`, HKDF and AES-GCM following RFC 9180's `LabeledExtract` / `LabeledExpand` and the key schedule (single-shot, sequence number 0).
  - `aesGcmSeal(key, plaintext, aad)` / `aesGcmOpen(key, sealed, aad)`: random 96-bit nonce, output `nonce ‖ ciphertext ‖ tag`.
  - `generateAesKey()` (AES-256, extractable only where it must be wrapped), `hmacSha256(secret, bytes)`, `constantTimeEqual(a, b)`.
  - `apps/web/src/keys/base32.ts`: Crockford base32 encode/decode (no padding, case-insensitive, `I L O U` mapping as Crockford).
- Go `apps/runner/internal/keys/`: the same functions with `crypto/ecdh` (X25519), `crypto/hkdf` (Go 1.24 or later, the version of `.mise.toml`), `crypto/aes` + `crypto/cipher` (GCM), `crypto/hmac`, `crypto/subtle`; `base32.go`.
- Test vectors `packages/contracts/fixtures/crypto/`:
  - `hpke-rfc9180.json`: the RFC 9180 test vector for mode 0, KEM 0x0020, KDF 0x0001, AEAD 0x0002 (from RFC 9180 Appendix A.1.1), checked by both sides (`open` of the given ciphertext, and `seal` with the given ephemeral key through a test-only seam).
  - `crewdeck-wrap.json`, `aes-gcm.json`, `hmac.json`, `base32.json`: Crewdeck's own uses generated once by the Go side (`go test ./internal/keys -run TestGenerateVectors -update`), opened by TypeScript.
  - `apps/web/src/keys/crypto.spec.ts` (Vitest browser mode, Chromium) and `apps/runner/internal/keys/vectors_test.go` read the same files.
- A test-only seam to fix the ephemeral key and the nonce (`withDeterministicRandom(seed)`), absent from the production bundle (the build test asserts the symbol is not in `dist/`).

## Decisions already made

- No third-party crypto library on either side (ADR 0003); only WebCrypto and Go's standard library.
- `info` strings: `crewdeck/v1/vault-wrap`, `crewdeck/v1/item-key`, `crewdeck/v1/session-key`; additional data is always explicit (the ids it binds), never empty except for the RFC vector.
- All byte strings travel as base64url without padding in JSON.
- WebCrypto's X25519 is required: Chrome 133+, Safari 17+, Firefox 130+. On a browser without it, `apps/web/src/keys/support.ts` returns false and the page says « Ce navigateur ne peut pas chiffrer de bout en bout. » (copy key `keys.unsupported`); no fallback.

## Acceptance criteria

- [ ] The RFC 9180 vector opens and reseals identically in TypeScript and Go.
- [ ] Every Crewdeck vector generated by Go opens in TypeScript, and a TypeScript seal opens in Go (a round-trip test through a fixture written during the test run).
- [ ] A ciphertext with one flipped bit or wrong additional data fails to open on both sides.
- [ ] Base32 round-trips and decodes the Crockford aliases; HMAC and constant-time comparison match the vectors.
- [ ] `docs/security/e2e.md` describes every primitive with its exact bytes.
- [ ] The deterministic seam is absent from the production web build.
