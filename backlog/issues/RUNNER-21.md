## Context

US-112: a stuck agent must never burn a night of the Pilote's **Comptes IA**. A **Session** that sends no event for 15 minutes, or that is active for 45 minutes without progress (a change to the files of its worktree, or a write of its Sorties: a report, a comment, a verdict, a document), is interrupted; both durations are the Pilote's, per **Rôle** (PARAM-5). A Session that waits for the Pilote (a question, a permission request, its turn over and its next message awaited) never counts: that wait is already the Pilote's **Décision**. The Runner is the only one that sees the worktree and the Moteur's events, so it is the one that measures (ADR 0004); the server learns a state and a reason, never content (ADR 0003). This ticket is the measuring and the interruption; the StepRun, the Décision « Session sans progrès » and the panel's banner are SESSION-4.

## Current state of the code

- `apps/runner/internal/session/manager.go`: `Manager` (`sessions map[string]*live`), `Start`, `Resume`, `Stop`, `halt` (a stop done: state `stopped`, worktree and Moteur's id kept), `runSession` (the `for event := range run.Events()` loop: `logEvent`, then `setState`: `waiting` on a `question`, a `permission-request` or a `result`, else `active`), `track` (the requests that wait, `session.waiting` / `session.answered`), `report` (`protocol.NewSessionState`), `drop`. No timer, no file watcher: a Session whose Moteur hangs stays `active` for ever.

An Étape's Session (`rec.Step != nil`) works alone and ends with its turn (`manager.go`, the `Result` case); a Session without `Step` is the Pilote's conversation, which waits for their message after each turn.
- `apps/runner/internal/session/step.go`: the socket ops `step.start`, `step.report` (`OpStepReport`, sends `protocol.NewStepReport`), `step.ask`, `step.answer`; `sendVerdict`. `apps/runner/internal/mirror/` has no notion of a Session: a Miroir write is not attributed to one.

Go types are generated by `pnpm exec nx run contracts:generate` into `apps/runner/internal/contracts/`.

## To do

- **Protocol** (`packages/contracts/src/runner/session.ts`, shared fixtures in `packages/contracts/fixtures/runner/`, valid in TypeScript and Go, `pnpm exec nx run contracts:generate`):
  - `zSessionThresholds = z.object({ silentMs, stalledMs })` (positive integers, milliseconds); `session.start` and `session.resume` carry `thresholds` (required; the server fills them, the Runner keeps them in `session.json`).
  - `session.state` gains `interruptedReason: 'no-event' | 'no-progress'` (only with `state: 'interrupted'`) and `idleSinceAt` (ISO instant: the last event for `no-event`, the last progress for `no-progress`).
  - `SESSION_INTERRUPTED_REASONS` (`api/sessions.ts`) = `['runner-offline', 'runner-restarted', 'no-event', 'no-progress']`; `zAgentSession` gains `idleSinceAt: string | null`.
- **Runner** `apps/runner/internal/session/watchdog.go`, with an injected `Clock` (`Now()`, `NewTicker(d)`; the tests drive it):
  - per Session that runs an Étape (`rec.Step != nil`; the Pilote's own conversation has no threshold: it is only ever waiting for them or working under their eyes), `lastEventAt` (set on each event of the Moteur's stream, in `runSession` next to `logEvent`) and `lastProgressAt`.
  - progress is either a change of the worktree's fingerprint, polled every 30 s, or a write of the Session's Sorties: the `etape report` op of its step (`OpStepReport` in `step.go`), the one write of the Sorties the Runner sees per Session (a Review's comment goes through the Miroir, then its verdict through `etape report`). The fingerprint is the hash of `git status --porcelain=v1 -z`, `HEAD`, and for each path the status lists its size and modification time (so that editing a file already modified still counts); `git` runs with the same environment as the Session's other git calls, a failure of it is no progress and no error.
  - the clock of both restarts at the instant the Session starts, and at the instant it leaves a pause. Paused (nothing counts, nothing is interrupted) while a question or a permission request waits (`live.pending` not empty) and while the Session's state is `waiting` for the Pilote's message; the pause ends on the answer, on the Pilote's message (`Input`), on the Session's resume.
  - at each tick and each event, a threshold crossed (`now - lastEventAt >= silentMs`, or `now - lastProgressAt >= stalledMs`; the one crossed first wins, `no-event` on a tie) stops the Moteur as `Stop` does (interrupt, then cancel after `StopGrace`), then `halt` records state `interrupted` with the reason in `session.json` (`record.InterruptedReason`, `IdleSinceAt`), reports it with `session.state`, and keeps the worktree and the Moteur's id for a resume. A stop by the Pilote or the Runner stopping wins over it; a Session that ends by itself in the same instant is not interrupted.
  - an interrupted Session is not alive: its restart is the server's, as for any interrupted Session (`hello` reports it not alive; the server never overwrites a `no-event` or `no-progress` reason with `runner-restarted`).
  - `Manager` creates the watchdog in `New`, closes it in `Close`.
- **Server** (`apps/server/src/sessions/`): `AgentSessionInterruptedReason` gains `no_event @map("no-event")`, `no_progress @map("no-progress")`, and `AgentSession.idleSinceAt DateTime? @map("idle_since_at")`; one migration. `SessionsService.start` and `resume` fill `thresholds` from `SettingsService.effective(pilotId, projectId).thresholds[role]` (minutes to milliseconds; `startMessageOf(row, thresholds)`), `report` stores the reason and `idleSinceAt` as given (cleared when the Session leaves `interrupted`), and `reconnected` leaves an already `interrupted` Session as it is. The row stays resumable (`RESUMABLE_SESSION_STATES` unchanged). `apps/server/src/errors/messages.ts` has no new message: nothing is refused. Raising the Décision and moving the StepRun are SESSION-4's, hooked on `SessionHooks.onChanged`.
- **Tests**: `apps/runner/internal/session/watchdog_test.go` (fake clock, fake Moteur `engine/fake`, a temporary git worktree), `manager_test.go` for the wiring, `packages/contracts` fixtures, `apps/server/src/sessions/sessions.service.spec.ts` and the integration file `sessions` for the thresholds and the stored reason.

## Decisions already made

- The Runner measures, the server only stores a reason and an instant: no worktree path, no file name, no event content crosses (ADR 0003, ADR 0007: nothing is computed from the `events` table, which is purged after 7 days).
- Thresholds travel in the `session.start` and `session.resume` messages: a Runner never reads the Pilote's Paramètres. A change of Paramètres applies to the Sessions started or resumed after it; a running Session keeps the thresholds it was given.
- « Progress » is deliberately narrow: events alone (an agent looping on the same tool calls, as in the mockup) are not progress, which is the point of the second threshold; « no event » is for a Moteur that hangs.
- A Session that waits for the Pilote (a question, a permission, its turn over awaiting their message) is paused, never stalled: its wait is the Pilote's Décision already (US-112, US-17).
- The fingerprint includes size and modification time of the changed paths: `git status` alone says « M file » before and after the next edit, which would read a busy agent as stuck.
- Only Étape Sessions (a StepRun) are watched at the MVP; a Commande's run has its own timeout (PROCESS-12).
- The Moteur is stopped, not killed: the Moteur's own session id stays, so « Reprendre la Session » (SESSION-4) resumes it.

## Acceptance criteria

- [ ] With the clock driven, a Session whose Moteur emits no event for `silentMs` is interrupted with `interruptedReason: 'no-event'`; the worktree and `engineSessionId` are kept; the server's AgentSession is `interrupted` with that reason.
- [ ] A Session that keeps emitting events but changes no file and writes no Sortie for `stalledMs` is interrupted with `no-progress`; one file edit, one commit, or one `etape report` before the threshold restarts that clock.
- [ ] Editing a file already modified counts as progress (fingerprint with size and modification time); a failing `git status` interrupts nothing by itself.
- [ ] While a question or a permission request waits, or the Session's turn is over awaiting the Pilote's message, nothing is interrupted however long it lasts; after the answer or the message, both clocks restart from that instant.
- [ ] A Session the Pilote stopped, or that ended, is never reported interrupted afterwards; a Session without a StepRun is not watched.
- [ ] `session.start` and `session.resume` carry the Rôle's thresholds in milliseconds (a custom Rôle at 15 and 45 by default); a Session resumed after a change of Paramètres uses the new ones.
- [ ] After a Runner restart, a `no-progress` Session stays `interrupted` with its reason (not `runner-restarted`).
- [ ] The new fields are valid in TypeScript and Go from the same fixtures; `contracts:generate` leaves no diff.
